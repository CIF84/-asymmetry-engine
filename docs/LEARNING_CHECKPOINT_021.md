# Learning Checkpoint — Spec 021

**Checkpoint date:** 2 September 2026  
**Scope:** Spec 021  
**Relationship:** Continuation of learning checkpoints 001–019 and 020.

## Outcome

Spec 021 returned **C — NO SURVIVOR, RADAR WORKED**.

Eleven concrete opportunity hypotheses were screened in approximately 20 minutes of active research, with €0 paid data and no implementation. Nine died during shallow screening and two after one additional bounded exact-resolution audit.

This is the first direct evidence that the research-policy change learned in Spec 020 can be applied successfully to a fresh candidate set.

```text
EV PATH
multiple specs
→ technical deepening
→ exact competitor discovered

SPEC 021
11 candidates
→ early exact-resolution search
→ ~20 minutes
→ €0
→ 11 explicit kills
```

The important result is not that no opportunity survived. It is that weak candidates were eliminated before expensive feasibility, demand measurement, or implementation work.

## 1. Reinforced learning: RADAR evaluation improved

Spec 020 suggested moving exact-resolution search earlier.

Spec 021 applied that policy successfully.

This strengthens, but does not permanently institutionalize, the working sequence:

```text
specific actor + decision
        ↓
economic consequence
        ↓
missing information
        ↓
recoverability
        ↓
EXACT RESOLUTION SEARCH
        ↓
residual gap?
      /       \
    NO         YES
    ↓           ↓
  PARK      deepen only as needed
```

Exact-resolution searches based on the hypothesized output were especially efficient. Searching for functions such as a buyer verdict, deduction-by-deduction evidence pack, or line-by-line challenge assessment discriminated better than broad category searches.

## 2. RADAR rejection is now empirically useful

Spec 021 reinforces the Spec 020 interpretation:

```text
RADAR VALUE
=
opportunities correctly advanced
+
opportunities cheaply rejected
```

A no-survivor run can be successful when candidates are rejected for concrete, decision-relevant reasons at low research cost.

The process must not manufacture a winner to demonstrate productivity.

## 3. New bottleneck: candidate generation quality

Spec 021 also exposed a new uncertainty.

The evaluation layer performed well, but the candidate set consisted largely of recognizable, economically important problem categories whose exact resolutions were already mature and easily discoverable.

```text
                 RADAR
                   │
          ┌────────┴────────┐
          │                 │
 CANDIDATE GENERATION    EVALUATION
          │                 │
         ???                ✓
                            ↑
                       021 strengthened
```

The next dominant question is therefore not merely whether RADAR can evaluate hypotheses efficiently.

It is:

> **Can RADAR generate sufficiently non-obvious, evidence-native opportunity hypotheses in the first place?**

A strong filter attached to a weak or obvious candidate generator can still produce no useful opportunities.

## 4. Do not simply repeat the same candidate-generation method

Repeating Spec 021 with another brainstormed set of familiar consumer problems would risk producing:

```text
familiar problem
→ exact solution search
→ cheap rejection
→ repeat
```

That would continue validating the filter while failing to improve discovery.

The next experiment should therefore change the **input-generation mechanism** while preserving the cheap evaluation policy.

## 5. Signal-native discovery hypothesis

The next candidate set should begin with observations rather than business ideas.

```text
RAW PUBLIC SIGNAL
        ↓
REPEATED / STRUCTURED PATTERN
        ↓
SPECIFIC ACTOR + DECISION
        ↓
MISSING INFORMATION / UNCERTAINTY
        ↓
ECONOMIC CONSEQUENCE
        ↓
OPPORTUNITY HYPOTHESIS
        ↓
CHEAP RADAR GATES
```

This is closer to the original Engine thesis, now informed by Specs 001–021.

Potential signal families include behavioral exhaust, structural change, and market friction. They are experimental source classes, not permanent architecture.

## 6. Candidate yield becomes an empirical question

Spec 021 suggests a future learning chain:

```text
RAW SIGNALS
    ↓
CANDIDATE HYPOTHESES
    ↓
SURVIVE CHEAP GATES
    ↓
FORGE CANDIDATES
```

RADAR should eventually learn which signal classes disproportionately produce:

- obvious already-solved problems;
- unrecoverable complaints;
- economically trivial friction;
- inaccessible experiments;
- or unusually strong unresolved decisions.

No numeric yield metric or source score is authorized yet.

## 7. A tentative negative prior

Spec 021 provides weak but useful evidence that highly visible, generic, high-value consumer decisions often already have mature resolution products.

This should not become a rule to avoid mainstream markets.

It suggests testing whether higher-yield opportunities are more often found at intersections such as:

```text
specific configuration
× changing rule
× fragmented evidence
× narrower actor
× meaningful economic consequence
```

The EV hypothesis initially had this structure.

The important challenge is to discover such structures from evidence rather than manually inventing them.

## 8. What is supported vs unproven

**Supported:** early exact-resolution search can dramatically reduce research depth for weak candidates.

**Not established:** it will remain equally effective across less obvious or more novel opportunity classes.

**Supported:** the Spec 021 candidate set could be discriminated cheaply.

**Not established:** RADAR can reliably generate high-quality candidates from raw public signals.

**Supported:** exact functional output searches are efficient kill tests.

**Not established:** no-survivor candidate batches imply the underlying signal source is poor unless candidate generation itself began from that source.

**Supported:** evaluation policy improved relative to the EV sequence.

**Not established:** the Engine has improved end-to-end opportunity discovery until candidate generation also improves.

## 9. Next empirical question

> **Can fresh public evidence generate specific opportunity hypotheses that were not first conceived as familiar problem categories, while preserving the cheap rejection policy learned in Specs 020–021?**

This motivates Spec 022 — Signal-Native Opportunity Discovery.
